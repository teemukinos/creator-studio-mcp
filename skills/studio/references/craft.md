# Craft (headless, in a Linux container)

The storytold Craft editors (PhotoCraft, VectorCraft, EffectCraft, DesignCraft, FilmCraft) run headless in the `studio-craft` container, on local Docker or a remote container host. Each app's MCP server is an HTTP endpoint `<url>/mcp/<app>` behind a bearer token. Image, gateway and host checks: `craft/README.md` in the creator-studio-mcp repository. The Craft apps are third-party software by storytold; this skill only drives them.

- Where the host is: `CRAFT_URL`, else `~/.studio/craft/url`, else the local container `http://127.0.0.1:8080`. Token: `CRAFT_TOKEN_FILE`, else `~/.studio/craft/token`. Scripts and `craft_sync.py` read the same settings. Use a remote host when the Mac shouldn't do the work or isn't there. A remote host that suspends when idle can take a minute to answer the first call after a pause, and its `/work` may be empty again.
- Up-check: `python3 ${CLAUDE_SKILL_DIR}/scripts/craft_sync.py up` (`/health`, then `/status`: every `<app>-cli --version` and open sessions). The open route is `/health`; some platforms answer `/healthz` themselves (404). If the endpoints aren't connected in this assistant, register them once: `claude mcp add --transport http craft-<app> <url>/mcp/<app> --header "Authorization: Bearer <token>"`.
- Job lifecycle. A2: run the up-check, then push `assets/` to `/work/<job>/assets/`. Checkpoint: save each open Craft document under `/work/<job>/`, then pull what the user should see. Delivery (A8): pull the results into the job folder (`craft_sync.py pull <job>/out out/`), check them from the local files, then `craft_sync.py end <job>`, and stop the local container if no other job uses it.
- Files move only through the job's folder on the container, `/work/<job>/`. Push `assets/` before the first Craft stage, pull results after it (`craft_sync.py push`, `pull`; `handoffs.md`). Every path you give a Craft command is a container path under `/work/<job>/`, never a Mac path.
- The apps don't create missing folders. Create every output folder first: `craft_sync.py mkdir <job>/art/graded <job>/out …`.
- A restarted or new container has an empty `/work`: push `assets/` again and recreate the folders before resuming.
- Apps confine reads and writes to `/work` (FilmCraft has no such flag; the container user is its only limit). Keep it that way: don't ask a Craft app to read or write outside `/work/<job>/`.
- Each MCP session is one app process with its own open document. A session ends after 30 minutes idle; save the document (`.pcraft`, `.vectorcraft`, `.ecproj`, `.designcraft`, `.fcproj`) under `/work/<job>/` before a checkpoint.
- At most 3 sessions per app at once. Close each session when its stage is done (HTTP `DELETE` with its `Mcp-Session-Id`). When an app is full, a new session replaces the oldest session that has been quiet for 2 minutes and runs nothing. So a session paused longer than 2 minutes can lose its open document: save it first. Run long exports with `wait: true`, because a session waiting on its own export is never replaced.
- Tool names differ per app. PhotoCraft, VectorCraft, EffectCraft and FilmCraft have `command_list`, `command_run`, `command_batch`; DesignCraft has `list_commands`, `execute`, `batch`. Look up a command's params with the list tool (filter it) before the first call, not by trial.
- A known route is one call: `command_batch` (or DesignCraft `batch`) with every step. From Claude Code or Codex, a stage that needs several tools (PhotoCraft per image) runs as one script in `scripts/` that makes the MCP calls in one session.
- Long exports: FilmCraft `file.exportMedia` and EffectCraft `renderQueue.render` block until written, with `wait: true`. Budget about 4 minutes of render per minute of 1080p on 2 vCPU (FilmCraft); 4K roughly 4 times that.
- The `ui_*`, screenshot, pointer and click tools in the Craft tool lists drive a desktop app (`--bridge`, per FilmCraft's `docs/agents.md`); the container has none. Use the render and export tools.
- Checks are files, pulled to the Mac: `ffprobe` for video, `sips` or a viewed PNG for images, PDF page count. Never `ui_*` tools: no app window exists.
- Video delivery codec is H.264 (FilmCraft also ProRes 422 HQ, DNxHR, PNG sequence, GIF). No H.265 from FilmCraft on a GPU-less box.

## Recipes

- 2026-11-11, PhotoCraft 0.22.0: grade and resize an image set over MCP. Per image, in one session: `doc_open {"path": "/work/<job>/assets/photos/x.jpg"}`, then `command_batch {"steps": [{"id": "image.autoTone", "params": {}}, {"id": "image.adjustments.vibrance", "params": {"vibrance": 25, "saturation": 5}}, {"id": "image.imageSize", "params": {"width": 1600, "resample": "bicubicSharper"}}, {"id": "filter.sharpen.smartSharpen", "params": {"amount": 80, "radius": 0.8, "reduceNoise": 10}}]}`, then `doc_export {"path": "/work/<job>/art/graded/x-1600.jpg", "quality": 88}`, then `doc_close {}`. `imageSize` with width only keeps the aspect. 4 photos of up to 8256x5504 in 16 calls, 6.5 s on a local 2 vCPU container, about 20 s on a remote 2 vCPU host (same output bytes).
- 2026-11-11, PhotoCraft 0.22.0, CLI only (local container, not the gateway): `photocraft-cli batch --actions grade.json --in raw --out graded --format jpg --quality 88 --no-gpu` with the same four steps as a JSON list of `{"command", "params"}` (4 images of 3000x2000 in 4.4 s).
- 2026-11-11, VectorCraft 0.24.0: open and export, one call. `command_batch {"steps": [{"id": "file.open", "params": {"path": "/work/<job>/vector/x.vectorcraft"}}, {"id": "document.export", "params": {"path": "/work/<job>/out/x.pdf"}}]}`. Format comes from the extension (pdf, svg, png, eps, ai…). CLI form: `vectorcraft-cli run --in x.vectorcraft --export x.pdf --export x.png`.
- 2026-11-11, VectorCraft 0.24.0: a one-page sheet from scratch, one call (13 steps, 0.6 s): `file.new {"width": 842, "height": 595, "units": "Points", "colorMode": "rgb"}`; `shape.rectangle {x, y, width, height}` then `paint.setFill {"color": "#0b0f1a"}` and `paint.setStroke {"none": true}` (they apply to the new, selected shape); `text.create {x, y, text, size, color}` (y is near the top of the type: y 58 at 28 pt gave bounds y 30-67); `file.place {"path", "rect": [x, y, w, h], "link": false}` per image (fits inside the rect, aspect kept, centred; `link: false` embeds it); `file.saveAs {"path": "….vectorcraft"}`; `document.export` to `.pdf` and to `.png` with `"scale": 2`.
- 2026-11-11, DesignCraft 0.20.0: PDF of every page, `execute {"command": "file.exportPdf", "params": {"path": "/work/<job>/out/x.pdf"}}` (`standard`: x4, x1a or a2b for print). Page PNG: `export_png {"page": 0, "path": "….png", "scale": 2}` (Letter page: 1224x1584). CLI form, tried with the built-in sample: `designcraft-cli run --sample --all-pages out/ --export x.pdf` (4 pages in 0.6 s).
- 2026-11-11, EffectCraft 0.24.0: render a comp, one call. `command_batch {"steps": [{"id": "renderQueue.add", "params": {"comp": "<name>", "format": "h264", "output": "/work/<job>/video/x.mp4", "timeSpan": "custom", "start": 0, "end": 3}}, {"id": "renderQueue.render", "params": {"wait": true}}]}`. 1080p at about 9 render fps on 2 vCPU. CLI form, tried with the demo: `effectcraft-cli render --demo --out x.mp4 --progress` (300 frames in 33 s).
- 2026-11-11, FilmCraft 0.20.0: export the active sequence: `command_run {"id": "file.exportMedia", "params": {"path": "/work/<job>/out/x.mp4", "range": "entire", "wait": true}}` with a progress token. For a cut: `"range": "custom", "startSeconds", "endSeconds"`. 1080p H.264 at about 6 render fps on 2 vCPU (27 s demo: 107 s). The result's `seconds` is render time, not clip length.

## Dead ends

- 2026-11-11, DesignCraft 0.20.0: exporting into a folder that doesn't exist fails ("the folder … does not exist"). Create the folder first (`craft_sync.py mkdir`); FilmCraft creates its own.
- 2026-11-11, PhotoCraft 0.22.0: `doc_export` into a missing folder fails ("No such file or directory"). Same fix.
- 2026-11-11, PhotoCraft 0.22.0: with automation roots (as the gateway runs it), `file.automate.batch` and `file.openAs` are refused: "uses ambient filesystem paths and is disabled; use capability-scoped document methods". Use the per-image recipe.
- 2026-11-12, a remote host: `/healthz` returned 404 `{}` from the platform, not from the gateway. Use `/health`.
- 2026-11-12, PhotoCraft 0.22.0 on a host with no cgroup filesystem mounted: `doc_open` of any large photo failed with "0.0 GB is free". Fixed in the gateway: each app now gets its own read-only cgroup view (`/status` `startup.cgroup` says "own read-only view per app"). After a Craft update, run the repository's `craft/tests/host_check.py` against each host.
- 2026-11-11, FilmCraft 0.20.0: `filmcraft-cli mcp --automation-read-root …` exits 2: FilmCraft has no root flags. The gateway runs it without them.
